# BiLLiE website

A single-page marketing site with a qualification form. Practices find it, read
what BiLLiE does, submit their details, and Isaiah reaches out manually.

There is no product signup and **no database**. On submit, the form emails the
lead to `info@getbillie.com.au` (and sends the lead a courtesy auto-reply)
through AWS SES in Sydney. Every email BiLLiE sends is listed in
`docs/EMAIL-GUIDE.md`.

## This site is disposable

It has a planned death date: it gets rebuilt in **Framer** later. It is a
brochure, not the app. Keep it that way.

- **Zero coupling** to the BiLLiE monorepo. Do not import from, or change,
  anything in the app repo. Brand tokens are hardcoded in `tailwind.config.ts`.
- No auth, no sessions, no CMS, no shared packages, no persistence.

## Stack

- Next.js 15 (App Router), TypeScript strict
- Tailwind v3
- One route handler: `POST /api/lead` (Node runtime, `syd1` / Sydney)
- AWS SES v2 (`ap-southeast-2`) for outbound email, authenticated with Vercel
  OIDC (no AWS keys)
- `@vercel/analytics` (cookieless)

## Structure

```
src/
  app/
    layout.tsx           fonts (Jost, Cormorant Garamond, JetBrains Mono,
                         Kalam), metadata, analytics
    page.tsx             composes the home page sections
    privacy/page.tsx     the privacy policy (text in lib/privacy.ts)
    globals.css
    api/lead/route.ts    zod validate -> SES x2, honeypot, input caps
  components/            one component per section
  lib/
    copy.ts              SINGLE source of truth for every string. No copy
                         literals live in components.
    lead-schema.ts       one zod schema, shared by client + server
    privacy.ts           every word of the privacy policy, plus its dates
```

## Copy

All user-facing copy lives in `src/lib/copy.ts`. Components import from it.
Do not inline strings in components. The wordmark is exactly **BiLLiE**
(capital B, lowercase i, capital L, capital L, lowercase i, capital E).

## Environment

One variable, set in the Vercel project (Production and Preview):

```
AWS_ROLE_ARN=arn:aws:iam::<account-id>:role/billie-prod-website-mailer
```

- The role lives in AWS account for BiLLiE and may only call `ses:SendEmail`
  on the `getbillie.com.au` identity, From `info@` or `isaiah@` only.
- Vercel OIDC Federation (Team mode) must be on for this project. The function
  swaps its Vercel token for short-lived AWS credentials. There are no AWS keys.
- `getbillie.com.au` is already a verified SES identity in `ap-southeast-2`, so
  no DNS change is needed.
- Sends use the app's SES configuration set `billie-prod-default`, so bounces
  and complaints are recorded.
- The lead notification is sent from `info@`; the auto-reply is sent from
  `isaiah@` (with Reply-To `isaiah@`) so replies reach Isaiah directly.

## Develop

```
pnpm install

pnpm typecheck
pnpm build
```

## Deploy

Push to `main` on `github.com/Isaiahjdehoog/billie-website`. Vercel builds and
deploys via the existing GitHub connection. The custom domain
`www.getbillie.com.au` is attached (the apex redirects to www).

## Brand assets

Favicon and OG image in `public/` are generated by `scripts/gen-assets.mjs`
(see the header comment in that file). The generator tooling is not needed to
build or deploy - the assets are committed.
